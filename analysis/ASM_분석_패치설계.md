# ASM 분석 결과와 패치 설계 (방안 2: 2MB 확장 + 2,350자)

도구: `dis65816.py` (자체 제작 65816 디스어셈블러)

```
python dis65816.py 81858D 60 m16 x16
```

REA의 raw-binary 분석은 6502/x86/ARM/m68k만 지원하고 65816은 지원하지 않아서 직접 만들었습니다.
M/X 플래그는 직선 구간의 REP/SEP만 추적하므로, 분기 대상에서는 모드를 직접 지정해야 합니다.

## 1. 텍스트 경로 개요

```
[블록 번호 $0E39] --$80:D2D7 표(24비트×16)--> 블록 테이블 주소 → $AD/$AE/$AF
[메시지 번호 $0E38] → LDA [$AD],y(Y=번호×2) → $AD(하위 16비트만 교체, 뱅크 유지)
대화 루프 $81:858D → 1바이트 읽기 $81:8B3C (LDA [$AD]; INC $AD)
   ├ <F0     : 1바이트 글자 (폭 2단위)
   ├ F0~F2 xx: 2바이트 글자 코드 0x100~0x3FF (폭 3단위)   ← $81:85AF~85C1
   └ F3~FF   : 제어 코드 → 점프 테이블 $81:88E4
글리프 그리기 JSL $80:C90E
   ├ 코드 <0x100 : [$F4]+코드×16                      (8×16, 1bpp)
   └ 코드 ≥0x100 : $80:CBC6  Y = 코드×32 − $1000      (대화창 경로, $0E1A bit15=1)
                   $80:CA09  Y = 코드×32 − $2000      (다른 창 경로)
폰트 포인터 $F4/$F7/$FA/$FD ← $90:8003 (= $10:8856) 기준 +0/+8/+16/+24   ($80:8658)
```

- 1단위 = 4px입니다. 가나는 8px(2단위), 한자는 12px(3단위)이고, 한 줄 최대 폭은 `$0E34`입니다.
- `INC $AD`는 16비트만 증가하므로 **문자열이 뱅크 경계를 넘으면 안 됩니다.**

## 2. 핵심 테이블

### `$80:D2D7` (파일 0x52D7) — 대사 블록 표, 3바이트 × 16

| # | 주소 | 비고 |
|---|---|---|
| 00, 09, 0A | $08:8000 | 세이브·게임오버 등 |
| 01 | $08:831E | 전투 대사 명령 인덱스 |
| 02 | $09:8000 | |
| 03 | $09:CA78 | |
| 04 | $0A:8000 | |
| 05 | $0A:BBCA | |
| 06 | $0B:8000 | |
| 07 | $0B:AC60 | |
| 08 | $0C:DF32 | |
| 0B | $08:9293 | |
| 0C | $0B:E1A3 | |
| 0D | $0B:F3AF | |
| 0E | $08:9AF6 | |
| 0F | $08:D00F | |

→ 포인터 조사에서 찾은 블록 14개와 정확히 일치합니다.
**블록을 새 뱅크로 옮기려면 이 표의 3바이트만 바꾸면 됩니다.** 블록 안의 16비트 포인터는 같은 뱅크 기준으로 다시 계산합니다.

### `$80:D277` (파일 0x5277) — 시스템 텍스트·창 레이아웃 표, 3바이트 × 32

| # | 주소 | 내용 |
|---|---|---|
| 00~02 | $03:BB0F / $03:D830 / $03:EB51 | 시스템 메시지·창 레이아웃 |
| 08 | $0C:BD77 | **프롤로그·엔딩·상태창 레이아웃** (0x63D77 테이블, 128항목) |
| 10 | $06:D339 | 파일럿 풀네임 |
| 11 | $06:DA4E | 파일럿 약칭 |
| 12 | $06:DF33 | 유닛명 |
| 13 | $06:E570 | 무기명 |
| 14~16 | $06:EEFC | 추가 무기명 |
| 17 | $06:F2DE | 지형 |
| 18 | $06:F6B7 | 메뉴 |
| 19 | $06:F4CF | 커맨드 |
| 1A | $06:F591 | 무기 속성 |

- 대사의 `FA xx`(이름 삽입), `F6`(서브루틴 호출) 등이 이 표를 사용합니다.
- 이름류와 프롤로그·엔딩도 **이 표만 바꾸면 재배치할 수 있습니다.**
- 이름 테이블은 표 시작부터 그대로 씁니다. 0번 항목은 빈 문자열(`FF`)이고, 10·11번 표의 1~2번 항목은 `$109B` 같은 **WRAM 주소**(플레이어가 정한 이름 등)입니다. (예전 문서의 "6바이트 앞, 인덱스 3부터" 추정은 틀렸습니다.)

## 3. 제어 코드 (대화 점프 테이블 `$81:88E4`) — 2026-11-18 핸들러로 전부 확인

| 코드 | 길이 | 핸들러 | 내용 |
|---|---|---|---|
| F3 | 1 | 866A | 줄바꿈 |
| F4 | 1 | 866D | 키 입력 대기 |
| F5 | 2 | 8689 | 대기 프레임 수 등(`INC $AD`) |
| F6 a t | 3 | 86BF | 서브루틴 호출: `$80:D277`의 t번 표, a번 항목. 복귀 주소는 `$0E1F` 스택에 저장 |
| F7 n p… | 2+2n | 8719 | 무작위 분기 |
| F8 s x y | 4 | 8731 | 하위 명령(테이블 $81:8904). **s=06/07이면 `x y`가 포인터인 유닛 조건 분기**, 0~5는 포인터 없음 |
| F9 pppp | 3 | 873E | 워드 ≥ $8000: 무조건 점프(문자열 끝) |
| F9 ffff pppp | 5 | 873E | 워드 < $8000: 하위 10비트 플래그, 상위 바이트 0~3/4~7로 조건이 반대인 점프 |
| FA x | 2 | 8755 | 하위 명령(테이블 $81:8924). 0~3: 대기, 4~7: 이름 삽입(호출 형태) |
| FB ffff | 3 | 8762 | 플래그 켜기/끄기(0~3/4~7), 08: `$8C` 설정 |
| FC | 1 | 8772 | 창을 지우고 새 페이지 |
| FD x | 2 | 8835 | 얼굴 |
| FE | 1 | 8873 | 아무 동작 없음 |
| FF | 1 | 8876 | `F6` 호출 중이면 복귀, 아니면 끝 |

`build/srwtext.py`의 토크나이저가 이 표를 그대로 씁니다.

창 레이아웃 해석기 `$80:C7F5`(점프 테이블 `$80:D257`)는 F0~FF를 다른 의미로 씁니다.

- F0: 화면 채우기, F1: 속성, F2: 표 선택 등
- 텍스트 모드(`$2A` bit6)일 때만 F0~F2를 한자 접두로 처리합니다(`$80:C82D`).
- 비텍스트 모드에서는 **E8~EF가 팔레트 코드**입니다(`$80:C810`). 이 모드에서는 한글 접두와 충돌하지 않습니다.

## 4. 패치 설계

### 4-1. ROM 확장

- 1.5MB → **2MB** (0x180000~0x1FFFFF 추가, 뱅크 $B0~$BF).
- 헤더의 ROM 크기 바이트는 이미 `$0B`(2MB)라 바꿀 필요가 없습니다. 체크섬만 다시 계산합니다.

### 4-2. 한글 인코딩

| 범위 | 내용 |
|---|---|
| `00~E7` | 1바이트: 기호·영숫자(가나 자리는 사용하지 않거나 기호로 재사용) |
| `E8~EF xx`, `F0~F2 xx` | 2바이트 한글 = 11 × 256 = 2,816칸 (KS X 1001 2,350자 + 여유) |

- 내부 코드는 E8→0x400…EF→0xB00, F0→0x100…F2→0x300로 둡니다.
  (예: 한글 인덱스 = 접두 순서 × 256 + xx)
- 패치 지점
  - **대화**: `$81:85AF` `CMP #$00F0 / BCC` → E8~F2를 접두로 받는 서브루틴으로 JSL
  - **창 텍스트 모드**: `$80:C82D`도 같은 방식으로 수정
- 폭 계산(`$81:85C4` CMP #$0100)은 그대로 둬도 됩니다. 2바이트 글자는 모두 3단위(12px)입니다.

### 4-3. 글리프 주소 (여러 뱅크 폰트)

- 한글 폰트는 기존 한자와 같은 형식입니다: 32바이트 = 왼쪽 8×16 + 오른쪽 8×16, 1bpp, 12×12 사용.
- 뱅크당 1,024자 → 2,816칸 = 약 2.75뱅크.
  `$B0:8000`부터 배치합니다(인덱스 i → 뱅크 `$B0 + i>>10`, 주소 `$8000 + (i&$3FF)×32`).
- `$80:CBC6` / `$80:CA09`의 `ASL×5 / SEC / SBC`를 JSL 훅으로 바꿉니다.
  1. `$F6/$F9/$FC/$FF`(뱅크)와 `$F4/$F7/$FA/$FD`(주소)를 한글 폰트 쪽으로 설정합니다.
  2. Y를 계산해 원래 루프로 돌아갑니다.
  3. 루프가 끝나는 RTL 직전(`$80:CA63` / CBC6 경로의 RTL)에서 원래 포인터($10:8856 기준)로 복원합니다.
- 패치 코드는 뱅크 $80의 빈 공간이 없으면 $B3 이후에 두고 JSL로 부릅니다.
  뱅크 $82:FA30(1,488B)·$83:F27E(3,458B)의 빈 공간도 쓸 수 있습니다.

### 4-4. 텍스트 재배치

1. 블록(테이블 + 문자열)을 뱅크 $B3~$BF에 하나씩 배치합니다.
   번역 후 한 블록이 32KB를 넘으면 블록을 둘로 나누고 `$80:D2D7`의 미사용 항목(09/0A 등)을 쓰는 방안을 검토합니다.
   이 경우 게임 쪽 블록 번호 사용처를 추가로 분석해야 합니다.
2. `$80:D2D7`의 해당 항목을 새 주소로 바꿉니다.
3. 블록 안의 테이블 포인터, 전투 대사 명령(F7/F9), 문자열 안의 F9/F7 포인터를 새 오프셋으로 다시 계산합니다.
4. 이름류·프롤로그·엔딩은 `$80:D277` 항목을 바꿔 같은 방식으로 재배치합니다.

## 5. 남은 확인 사항 (에뮬레이터 실측 권장)

- `$0E1A` bit15에 따라 CBC6(−$1000) 경로와 CA09(−$2000) 경로 중 어느 쪽을 타는지. 각 경로의 `$F4` 값이 같은지(현재는 $80:8658 한 곳에서만 설정되는 것을 확인).
- 창 레이아웃 해석기의 F3~FF 의미 (프롤로그·엔딩·상태창 번역에 필요).
- FB/FA 하위 명령 테이블($81:8914/8924/8934)의 인자 길이.
- 압축 그래픽(타이틀 등) 해제 루틴.
- 대화창 한 줄 폭 `$0E34` 값(한글 12px 기준으로 한 줄에 몇 자가 들어가는지).
