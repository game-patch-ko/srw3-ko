# 제3차 슈퍼로봇대전 (SFC, J) — 한글화 사전 분석

## 1. ROM 기본 정보

| 항목 | 값 |
|---|---|
| 파일 | `Dai-3-Ji Super Robot Taisen (J).smc` |
| 크기 | 1,572,864 바이트 (0x180000, 12Mbit), 카피어 헤더 없음 |
| CRC32 / MD5 | `DFE9CC90` / `b5974f5306e8daee96d5fc625e960f0a` |
| 매핑 | LoROM (헤더 $00:FFC0 = 파일 0x7FC0, map mode $20, SlowROM) |
| 내부 제목 | `ﾀﾞｲ3ｼﾞｽｰﾊﾟｰﾛﾎﾞｯﾄﾀｲｾﾝ` |
| 카트리지 | type $02 (ROM+RAM+배터리), SRAM 8KB, 지역 $00(일본), 제작사 코드 $D9 (반프레스토), ver 1.0 |
| 체크섬 | $F0B1 / 보수 $0F4E — 정상 (12Mbit 미러 방식 합산과 일치) |

주소 변환 (LoROM): `파일 오프셋 = (bank & 0x7F) * 0x8000 + (addr - 0x8000)`

## 2. 폰트 (무압축, 1bpp)

- 위치: 파일 0x80858~ ($90:8858), 뱅크 $90
- 가나/기호: **8×16 셀 1bpp, 글자당 16바이트**, 코드 `nn` → `0x80858 + nn*16` (실제 사용은 8×12)
- 한자: **16×16 셀 (좌 8×16 + 우 8×16), 글자당 32바이트**, 768자
  - 코드 `F0 xx`/`F1 xx`/`F2 xx` → 인덱스 `(prefix-0xF0)*256 + xx` → `0x81858 + 인덱스*32` (실제 사용은 12×12)
  - 폰트 끝: 0x87858
- 다른 그래픽(뱅크 $93~$A3 등)은 압축되어 있음 → 타이틀 로고/전투 문자 그래픽 등은 별도 압축 해석 필요

## 4. 텍스트 배치

| 영역 | 내용 |
|---|---|
| 뱅크 $88~$8B (0x40000~0x5FFFF) | 시나리오 대사. 각 뱅크 선두에 16비트 포인터 테이블 ($88: 64개, $89~$8B: 256개) |
| 뱅크 $88 0x40485~ | 이벤트 스크립트 바이트코드(`FA 05 F7 n ptr…`, `F9 ptr` 등)가 대사 포인터를 직접 참조 |
| 뱅크 $8B 0x5ACA6~ 등 | 추가 포인터 테이블 (스테이지별 테이블이 여러 개 존재) |
| 뱅크 $8C 0x64300~0x67284 | 엔딩/후일담 텍스트 |
| 뱅크 $86 0x35400~ | 파일럿 이름 (포인터 테이블 + FF 종료 문자열) |
| 뱅크 $86 0x36100~0x37300 | 유닛명, 무기명 |
| 뱅크 $86 0x37500~ | 커맨드 메뉴(移動/発進/攻撃/説得/…), 정신 커맨드명 |
| 뱅크 $83 0x1C4E0~ 부근 | 시스템 메시지(반격 설정 설명 등) |

- 포인터는 **뱅크 내부 16비트**(뱅크 바이트는 코드에서 결정)
- 덤프 결과: `script_bank88.txt` ~ `script_bank8B.txt` (선두 테이블 기준만)
- **전체 포인터 조사 결과는 `포인터_조사.md`, `pointers.csv` 참조** / 방안 비교는 `한글화_방안_비교.md`

## 5. 빈 공간

- 대사 뱅크 $88~$8B는 사실상 꽉 차 있음
- 자잘한 빈 공간 합계 약 29KB (뱅크 끝의 FF 영역들)
- 12Mbit → 16/24/32Mbit LoROM 확장이 필요할 가능성이 높음

## 6. 한글화 관점의 핵심 과제

1. **한글 폰트 공간**: 가나는 8px 폭이라 한글을 넣을 수 없음 → 한글은 16×16(12×12) 2바이트 코드여야 함.
   현재 2바이트 영역은 `F0~F2` × 256 = 768자뿐이며 `F3~FF`는 제어 코드라 접두를 늘릴 수 없음.
   → (a) 한자 768칸 + 가나 160칸을 한글 약 900자로 재배치(빈도 상위 음절만), 또는
   (b) 폰트 출력 루틴을 수정해 KS X 1001 2350자 / 확장 뱅크 폰트 지원
2. **텍스트 용량 증가**: 가나 1바이트 → 한글 2바이트. 대사 뱅크가 이미 꽉 차 있어 ROM 확장 + 텍스트 재배치 필요.
   포인터가 뱅크 내부 16비트이므로 뱅크 선택 코드 분석이 필요.
3. ~~제어 코드 인자 길이 확정~~ → 완료(`ASM_분석_패치설계.md` 3절)
4. **포인터 전수 조사**: 뱅크 선두 테이블 + 스테이지별 추가 테이블 + 이벤트 스크립트 내 포인터 모두 수집.
5. **압축 그래픽**: 타이틀 화면, 전투 화면의 그래픽 문자 등은 압축 해제 루틴 분석 후 처리.
6. **줄 길이**: 대화창 한 줄은 대략 전각 20자 내외 — 실제 폭은 에뮬레이터로 확인 필요.
